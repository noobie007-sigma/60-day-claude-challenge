Bridgehead is built for professionals crossing into adjacent technical territory — pick a depth above, name the concept, and it'll give you a straight, structured explanation instead of a wall of prose.
▶ How this was built

System prompt design

The underlying Claude call is constrained to one job: turn one concept into a fixed four-part schematic — definition, analogy, example, quiz — returned as strict JSON so the UI never has to guess at structure. The prompt encodes the audience (technically literate professionals moving into an adjacent domain), so explanations skip beginner hand-holding but never assume the specific sub-field. Tone is locked to "blunt/expert": short sentences, no hedging, no motivational filler.

Edge cases are handled explicitly in the prompt rather than left to chance: nonsense or empty input returns a clarify response instead of hallucinating a concept; requests for harmful technical uplift (weapons, exploits, etc.) are declined in-character rather than breaking format; and if a concept is genuinely under-specified ("explain the algorithm"), the model asks one narrowing question instead of guessing.

Why the UI looks like this

The interface borrows from engineering schematics and blueprint annotation rather than a generic chat bubble — dotted connector lines, corner labels, and monospace annotations — because the product's whole premise is "structured technical breakdown," not casual conversation. The depth ruler is styled like a measuring instrument because depth actually is the one dial the user is turning each session.

Quiz options are interactive rather than plain text so the user gets a real recall check, and follow-up chips are auto-suggested from the response so the back-and-forth (a core input mode from the brief) has zero typing friction.

Extending this

  • Memory: persist the running list of concepts explained this session (and their depth level) into the request payload, so later explanations can reference "like the pod example earlier."
  • Tools: add a web-search or documentation-lookup tool call so explanations of fast-moving topics (new frameworks, APIs) can cite current docs instead of relying on training data.
  • Multi-step flows: chain explanation → quiz → adaptive follow-up, where a wrong quiz answer automatically triggers a re-explanation at a simpler depth before moving on.
  • Spaced repetition: log quiz results client-side and resurface concepts the user got wrong after a delay.
